# Augment planned-diff roadmap

Known gaps between shipped behavior and `src/augment/SPEC.md`.

- [x] Persist task and protocol-session state across daemon restarts: standalone JSON-RPC and MCP servers atomically snapshot every accepted mutation (0600 temp file, fsync, rename), validate entries on recovery, expose `task/list` and MCP `plan_list`, and use repository-scoped default storage or `--state-file`; the TUI separately persists task snapshots, agent-session bindings, and bounded session output.
- [x] Add a repository watcher that turns worktree path changes and HEAD movement into `node/stale` operations: `src/tui/repository-watch.ts` polls tracked and non-ignored untracked paths, detects edits/creates/deletes/renames and basis changes, queues events during controller operations, and re-baselines after Neolit-owned apply writes while allowing commit-driven HEAD movement to stale remaining planned paths. The controller closes the watcher on dispose.
- [x] Track patch lifecycle in core state (`drafted` → `applied` → `verified` / `failed`) and expose `patch/apply` plus `patch/verify` over JSON-RPC and MCP. Host apply is preflighted and transactional: snapshots restore bytes, modes, symlinks, and newly created directories if git apply or durable state recording fails. Verification checks whitespace and reverse-applies the complete patch series in a disposable worktree.
- [x] Add an OpenCode CLI `ModelRuntime` for the standalone TUI.
- [x] Project the planned tree onto the complete repository tree.
- [x] Add task-local locked paths with mutation rejection.
- [x] Keep candidate domains node-local and scope candidate paths to their owning node.
- [x] Keep OpenCode and Codex on the host-neutral `CliAgentRuntime` instead of adding provider-specific plugin SDKs: OpenCode uses its kept-alive v2 serve transport with CLI fallback; Codex uses its JSONL CLI backend and resumable thread ids. Both implement the same `ModelRuntime` contract, and agent tool access stays on the shared MCP protocol.
- [x] Persist and reload TUI tasks across process restarts.
- [x] Add a stable transport address (Unix socket) alongside stdio: the TUI (and any embedding host) serves its embedded server on `$XDG_RUNTIME_DIR/neolit/augment-<basename>-<hash>.sock` keyed to the repository directory (TUIs in different projects serve side by side; one owner per directory), mutation notifications broadcast to attached clients, and per-task serialization of mutating dispatch keeps concurrent writers from losing updates (a racing writer fails the optimistic-concurrency check instead of being overwritten by a stale-snapshot result).
- [x] Add protocol change notifications for multi-client tree views: `AugmentServer.onChange` emits task id/revision after durable mutation, stdio forwards `augment/taskChanged`, and the Unix socket broadcasts the same notification to all connected clients.
- [x] Add path-aware filesystem indexing: `src/tui/repository-index.ts` builds a bounded index of tracked and non-ignored source paths, resolves common relative imports and module references, ranks inbound/outbound/sibling relationships, refreshes from path metadata, and injects a compact scope-specific map into every model operation without sending indexed file bodies.
- [x] Validate patch content scope and locks: patch headers are parsed, one patch stays inside one file node, virtual patches project at their real path, and `task/restore` payloads pass the boundary schema plus referential integrity.
- [x] Add user/practice overlays and documentation-derived constraints: global `~/.config/neolit/overlay.md`, repository `.neolit/overlay.md`, and `.neolit/practice.md` become repository-wide typed constraints; root/nested `AGENTS.md`, `CONTRIBUTING.md`, `ARCHITECTURE.md`, and README documentation contribute imperative rules scoped to their owning directory. Constraints are attached before a new change task enters its marking window.
- [x] Add bounded re-crystallization with rejected-candidate memory: stale subtrees end staleness through `node/refresh` (optionally re-anchoring the basis), regeneration stays challenge-bounded, and labels eliminated by rejection or collapse cannot return.
- [x] Let models write into the plan through tools instead of one JSON reply: expose the planned-diff operations as agent tools over MCP, with `augmentd` as the tool provider (`augmentd --mcp`). Each call is small (one file's diff), validated and answered by the controller immediately (scope, locks, and — with `--directory` — joint `git apply` diagnostics returned to the agent so it retries that file with the exact reason). Controller authority is unchanged — every call flows through the reducers via the deterministic `domain/propose`, `domain/challenge`, `node/refine`, and `patch/attach` seams — and deterministic per-operation call caps keep agent loops bounded.
- [x] Wire an agent host (OpenCode MCP config, Codex, or Claude) to drive a task through the augmentd MCP tools end to end, and render tool-driven mutations live in the TUI as they land: agents attach with `augmentd --mcp --connect <socket>` (the TUI's winbar and the neolit.nvim sidebar show the served address), tool calls mutate the TUI's own task store, and external changes are adopted and repainted while the panel is idle. A write racing a running TUI operation queues behind it and then gets the typed stale-revision rejection with the fresh revision to retry.
- [x] Accept raw unified-diff text (no JSON envelope) for `draft-patch`/`repair-patch` replies: a unified diff is self-delimiting (`--- a/x`, `+++ b/x`, `@@`), so wrapping it in a JSON string only invites escape errors and mid-string truncation; assumptions move to trailing lines the runtime parses separately.
- [x] Route model calls through one kept-alive agent server instead of per-call CLI spawns: backends declare `serveArgs` (opencode: `opencode serve --port 0`), `PersistentAgentServer` in `src/tui/opencode-runtime.ts` keeps that process alive and reuses its printed address and password (`extractServerUrl`/`extractServerPassword` parse them), and every call runs as a warm HTTP exchange through the backend's `warmTransport` dialect — verified against a live OpenCode v2.0.13 host (basic auth with the printed password, `POST /api/session`, per-session `model`/`agent`, `prompt`, experimental `wait`, newest-first `message` list; ~300 ms transport overhead per call) with transport failures falling back to the one-shot CLI spawn and model-run failures failing the call. `test/augment-agent-backends.test.ts` covers the dialect, password capture, warm routing, and the CLI fallback.
- [x] Add Claude and Codex tool-session adapters: Claude receives a repository-scoped MCP config and allowed-tool filter; Codex receives isolated `--config` overrides for the same socket-backed MCP server, parses `thread.started`, resumes with `codex exec resume`, and streams MCP tool events. OpenCode retains its kept-alive warm serve path; Claude/Codex use their CLI session continuation.
- [ ] Complete live-host verification of Claude and Codex MCP tool sessions and the OpenCode warm tool-step path; the OpenCode warm step remains unverified against a live host.
